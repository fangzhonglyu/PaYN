## 1. Requirement and rules

- **Bit-exact to the kernels.** SC must match the scmp_kernels C-BSG integer matmul exactly, for any per-row stream
  length L from 1 to 128. That kernel is `~/repos/scmp_kernels`, where C-BSG is the only rule.
  - Kernel settings, from the traces in `~/repos/soren_scmp/sc_traces`: halve mode (7-bit grid), Owen bitrev scramble,
    64 masks, chunk_d 128, and per-row stream-length ladders.
  - `soren_scmp_kernel` only names that rule (`SC_MULT_SCHEME=cbsg`).
- **Read-only repos:** `~/repos/soren_PaYN`, `~/repos/soren_scmp_kernel`, `~/repos/scmp_kernels`, and `~/repos/soren_scmp`
  (traces only). Set `PYTHONDONTWRITEBYTECODE=1` when importing from them.
- **Shared files:** another session owns the INT variants `signed_segmented_csa_bp`, `_bp_ipd` and `_bp_sr`, plus
  `sweeps/int_mode/` and `build/power_char/tile_doubling_*`. Use copies only.
- **No triton/torch here.** The kernel model is a line-by-line numpy port.

How AF works:
- **A edge:** the A stream is high for its first kA cycles. kA is computed per element by a closed-form encoder: for each
  set bit j of L, add (b >> (7−j)) + [(b mod 2^(7−j)) > c_j], where c_j depends only on L and the column. This was
  checked against the kernel's `k_table` on all 1,056,768 (L, mask, b) cases.
- **W edge:** the W stream comes from an ungated, sample-ordered Sobol bank.
- **Mask:** hard-wired lane bits plus a 3-bit block-phase register. The register must reset at every slice/call start.
- **Why the count is exact:** C-BSG depends on A only through kA, so the AND count is exactly the kernel's count.

Routing note: AF and AF-IPD routes need the post-fill search-and-repair hook. NanoRoute's auto-stop skips repair above
about 1 marker per net. The hook is `apr/scripts/cbsg/postfill_search_repair.tcl`, driven by
`sweeps/cbsg/af/run_af_pinned_fix.sh postfill` and `sweeps/cbsg/af_ipd/run_af_ipd_pinned.sh`. Details are in
`build/power_char/cbsg_20261005/af/pinned_fix/README.txt`.

## 4. AF-IPD INT vs BOS (full bandwidth, 4x4 grid)

BOS (`designs/baselines/binary_os`) is an 8x8 output-stationary array with 24-bit accumulators at every precision:

| precision | GMAC/s/mm² | pJ/MAC |
|---|---:|---:|
| INT8 | 1,621 | 0.412 |
| INT6 | 2,064 | 0.260 |
| INT4 | 2,491 | 0.155 |

Its throughput figures are drain-excluded peaks. AF-IPD 4x4 composite: 538,299 µm².

| | current schedule (A bits in space, W bits in time) | all bits in time (section 5), estimate | BOS |
|---|---|---|---|
| INT8 peak | 1,522 (0.94×) | 1,522 | 1,621 |
| INT8 L=4096 / 1024 | 1,294 / 894 (0.80× / 0.55×) | ≈1,484 / 1,382 (0.92× / 0.85×) | 1,621 |
| INT6 L=4096 / 1024 | ≈1,658 / 1,070 (2 of 8 rows idle) | ≈2,600 / 2,320 (1.26× / 1.12×) | 2,064 |
| INT4 L=4096 / 1024 | 4,610 / 2,668 | ≈5,600 / 4,530 (2.25× / 1.82×) | 2,491 |

Energy (routed single PE):
- INT8: 0.352 pJ/MAC at peak, 0.391 at L=1024. BOS is 0.412.
- INT4: 0.088 at peak, 0.097 at L=1024. BOS is 0.155.

Why the current schedule loses throughput:
- A PE's 8 tile rows hold the 8 bits of one activation row, so each drain yields only 8 outputs.
- The drain takes 8×P_C cycles and the grid skew P_R+P_C−2. Together that is about 70% of the overhead.

Bandwidth:
- Full INT bandwidth is 1,024 bits per cycle per edge half. The SRAM is provisioned for SC at L=16, which is 576.
- With 576, INT is capped at 56% of peak.
- At the 4x4 boundary PaYN needs 4 / 3 / 1 bits per MAC (INT8 / INT6 / INT4). BOS needs 2 / 1.5 / 1.
- SRAM is excluded from every number above.

## 5. All-bits-in-time schedule (the user's proposal): runs on the current AF-IPD hardware with no RTL change

**Mapping:**
- Each tile holds one output. Tile row h is activation row i_h, and column v is weight column j_v, as in SC. A PE holds
  64 outputs.
- There is one pass per bit pair (h, q). Every row bus carries bit h of its activation row for the 128 elements of the
  chunk; every column bus carries bit q of its weight column.
- Each pass streams the whole reduction: L/128 data cycles.

**Order:** passes are grouped by significance level k = h + q, MSB first. For example:
- level 14: 7×7;
- level 13: 6×7 and 7×6;
- level 12: 5×7, 6×6 and 7×5;
- and so on down to level 0.

Within a level, passes just add. Between levels there is one lap, ×2, which takes 1 cycle with every-tile doubling.

| precision | passes | laps |
|---|---:|---:|
| INT8 | 64 | 14 |
| INT6 | 36 | 10 |
| INT4 | 16 | 6 |
| any BA × BW | BA·BW | BA+BW−2 |

**What carries each piece on the existing hardware:**
- **Bits:** the INT raw-bit ports (`a_raw_in`, `w_raw_in`). A-first's own A and W streams are silent because the
  magnitudes are 0.
- **Signs:** each pass has one sign, (h = 7) XOR (q = 7). Tie A's sign to 0 and load the pass sign on the W side every
  pass, with the existing `load_w_sign` wave.
- **Laps:** one `ring_in` pulse per level boundary. The per-PE ring_q wave handles the grid skew as before.
- **Readout:** tiles hold finished outputs, so read the 8 raw 24-bit row values from `acc_out_east` during the drain.
  The east combiner (Σ 2^h) is not used.

**Block period:** `BA*BW*NB + (BA+BW-2) + (P_R+P_C-2) + 8*P_C`, with NB = L/128.

**Range:** the 24-bit tile limits INT8 to L ≤ 511 in the worst case (|a·w| ≤ 2^14). BOS has the same limit with its
OW24 accumulators. INT6 allows L ≤ 8,191 and INT4 L ≤ 131,071. The current schedule allows INT8 L ≤ 65,535, because A's
bits are split across rows and combined in the 32-bit combiner. The user said to ignore range for now.

**Outside the array:** activations must arrive as bit planes, one bit per element per pass. That is the memory layout or
a feeder select.

**Prior evidence:** INT4 in this form, H(4,4) in the hybrid family, already ran bit-exact on the older BP grid RTL. The
evidence is in `sweeps/int_mode/bp/hybrid/` and `build/rtl_preflight/bp_hybrid*/`, with the cycle model in
`sweeps/int_mode/bp/model_lap_schedules.py`.

### Measured (2026-10-06): verified on the unchanged AF-IPD RTL and the qualified route

**Correctness.** The RTL is unchanged. Every drained `acc_out_east` value is compared against a numpy int64 GEMM.
- **Single PE:** 43/43 positive cases pass. They cover INT8 at L = 128 to 384, INT6 and INT4 at L = 128 to 4,096
  (plus INT4 at 16,384), and W4A8, W6A8 and W8A4. They include extremes up to 75% of the 24-bit range, junk inputs, a
  late `int_mode` and a parked AF counter.
- **Negative controls:** all 25 are caught: a missing lap, an extra lap, a wrong pass sign, a wrong level order, no
  bubble, an early drain and a block overlap. In each one the RTL matches an edge-level replay of the logged schedule,
  so the hardware did exactly what the wrong schedule asked for. The 2 contract controls are also caught.
- **2x2 and 4x4 grids:** 35/35 pass, 21 positive and 14 negative. Every PE laps on the r+c wave.
- **Block period:** every measured period equals `BA*BW*NB + (BA+BW-2) + (P_R+P_C-2) + 8*P_C`.
- **Existing checks:** the existing INT and switch checks were rerun on the extended bench. All 210 + 351
  trace/schedule/check files are byte-identical to before.
- **Routed GL:** max-SDF with `+neg_tchk`. It covers 19 energy points and 16 functional runs (junk, extremes and 5
  negative controls). All are bit-exact, and every GL trace matches its RTL trace.
- **Audit:** the strict audit fails only on the known 4 SDFCOM_IWSBA. They were approved with
  `--approve-annotated-interconnect`; the rationale is in the run directories. There are 0 post-reset timing
  violations, and the SAIF validation and INT SAIF audit pass.

| precision, L | 4x4 GMAC/s/mm², current → all-bits-in-time (BOS) | pJ/MAC (drain excluded), current → all-bits-in-time (BOS) |
|---|---|---|
| INT8, 384 | 529 → 1,198 (1,621) | 0.454 → 0.383 (0.412) |
| INT8, 256 | 399 → 1,082 | 0.505 → 0.399 |
| INT6, 1,024 / 4,096 | 1,070 / 1,658 (formula, 2 rows idle) → 2,319 / 2,597 (2,064) | not run → 0.207 / 0.201 (0.260) |
| INT4, 1,024 / 4,096 | 2,668 / 4,611 → 4,530 / 5,606 (2,491) | 0.097 / 0.0905 → 0.093 / 0.0895 (0.155) |
| W4A8, 1,024 | 1,334 → 2,563 | 0.1945 → 0.1847 |

How to read the table:
- **Throughput:** measured 4x4 RTL block periods at 400 MHz on 538,299 µm², with laps, skew and drain included. The
  current schedule uses its formula, which was verified on the IPD grid. The handoff's INT8 L = 1,024 / 4,096
  estimates are confirmed too (periods 564 / 2,100, so 1,382 / 1,484). Those lengths need a data-dependent range,
  which uniform data satisfies.
- **Energy:** routed single PE, PT-PX. The current-schedule controls ran on the same operands. Per-cycle power is
  about the same (18.0 to 18.4 mW), so the saving comes from MAC/cycle. At INT8 L = 384 that is 119.3 vs 99.1, since
  there are BA+BW−2 lap bubbles per BA·BW·NB data edges instead of BW−1 per BW·NB.
- **Drain included:** INT8 L = 384 is 0.389 vs 0.497, INT4 L = 1,024 is 0.095 vs 0.104.
- **Data only:** INT8 0.360, INT6 0.199, INT4 0.0885.
- **Class split:** the per-MAC drop is spread over tiles, pipes and clock. It does not come from one block.
- **Range:** INT8 is limited to L ≤ 384, so INT8 reaches only 0.74× BOS.
